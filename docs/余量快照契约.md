# 余量快照契约

| | |
|---|---|
| **版本** | 1.0 |
| **状态** | 现行（stable） |
| **适用范围** | `dsh-token-monitor` 插件所有提供方的余量/余额数据交换 |
| **读者** | 为插件新增提供方的贡献者、消费快照的前端代码维护者 |
| **规范性** | 本文使用「**必须** / **不得** / **应当** / **可以**」表述约束强度，与 RFC 2119 的 MUST / MUST NOT / SHOULD / MAY 对应 |

本契约定义**提供方抓取器**（服务端）与**前端渲染**之间唯一的数据交换格式。它的存在意义是：**新增一家提供方只需写一个抓取器 + 登记一行映射，前端零改动**。

---

## 0. 术语

| 术语 | 含义 |
|---|---|
| **快照**（snapshot） | 一次抓取产出的完整数据对象，本契约的全部内容 |
| **抓取器**（fetcher） | 每家提供方一个的 `fetchXxx(ctx, config)` 函数，负责取数 + 解析 + 封装 |
| **提供方**（provider） | 一个可查余额/额度的服务，由 `providerId` 标识（如 `kimi-coding`） |
| **计费类型**（billingType） | `quota`（订阅额度，按窗口限流）/ `balance`（按量余额，按金额扣费） |
| **时间窗**（timeWindow） | 订阅额度的一个限额周期（如 5 小时、7 天、计费周期） |
| **状态码**（status） | 1–7 的整数，表示本次抓取的结局 |
| **静态元数据** | 与单次抓取无关的信息（展示名、厂商、官网入口），不由快照携带 |

---

## 1. 设计原则

1. **一条规则只写一次**：判色、选窗口、拼文案，各只有一份实现，与提供方无关。
2. **协议只传事实，不传展示**：**不得**出现中文文案、**不得**出现预格式化的倒计时字符串。
3. **按类型取数据**：拿到快照先看 `billingType`，直接去 `quota` 或 `balance`，**不得**做"字段存在性探测"。
4. **各家自行封装**：原始响应差异由抓取器自己消化，直接产出合规结构；中心**不得**假设任何字段路径。
5. **校验兜底**：`validate()` 保证「写法自由、产出一致」。
6. **没有独有字段**：装不进结构的数据说明本来就不该展示；**不得**为单家提供方开字段。

## 2. 数据结构

### 2.1 公用层（所有提供方）

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `providerId` | string | **必须** | 提供方 id，必须与 `/token-monitor/provider-mappings` 的键一致 |
| `billingType` | `"quota"` \| `"balance"` | **必须** | 计费类型 |
| `status` | number | **必须** | 状态码 1–7，见第 3 节 |
| `message` | string \| null | 可以 | `status ≠ 1` 时的补充说明，须符合 3.3 节约束 |
| `links` | object | 可以 | 官方下发的操作入口，见下表 |

**约束**：`quota` 与 `balance` **不得**同时出现，且**必须**与 `billingType` 一致。

**`links`（可选）**：提供方给的跳转地址，前端优先用它、缺失时回退内置地址（`PROVIDER_URL_SEED`）。
只接受 `http(s)` 绝对地址；其它协议视为非法（防止 `javascript:` 之类注入）。

| 字段 | 类型 | 含义 |
|---|---|---|
| `topUpUrl` | string | 充值 / 续费页 |
| `usageUrl` | string | 用量 / 账单页 |

```jsonc
"links": {
  "topUpUrl": "https://platform.deepseek.com/top_up?from=dsh",  // 可以
  "usageUrl": "https://platform.deepseek.com/usage"             // 可以
}
```

### 2.2 `billingType = "quota"`

```jsonc
"quota": {
  "plan": "Plus",                   // 可以：套餐名或权益等级名（Free / Plus / Pro …）
  "timeWindows": [                  // 必须：至少一项
    {
      "period": "5h",               // 必须：5h | 7d | 30d | month（受控枚举）
      "usedPct": 12,                // 必须：已用百分比 0–100 的整数
      "resetAt": 1767000000000,     // 可以：重置时刻，毫秒时间戳
      "scope": "code"               // 可以：total（默认）| code（编程专项）
    }
  ],
  "extraQuotas": [                  // 可以：结转额度、加油包等附加额度
    { "label": "额外额度（结转）", "amount": 12.34, "currency": "CNY" },
    // 带消费进度的附加额度：limit 为 null 表示「无上限」
    { "label": "加油包", "amount": 0, "currency": "CNY",
      "progress": { "used": 12, "limit": 300, "currency": "CNY" } }
  ]
}
```

**`timeWindows` 规则**

- `period` **必须**是受控枚举 `5h` / `7d` / `30d` / `month` 之一；新增周期**必须**扩展枚举，**不得**引入自由字符串。
- `usedPct` **必须**是**已用**百分比（与官方控制台口径一致），**不得**填剩余。
- 窗口的展示文案由前端按 `period` 映射，快照**不得**传 `label`。
- 长周期由前端集合 `['7d', '30d', 'month']` 推导，快照**不得**传"是否长周期"的标记字段。
- 同一 `period` **可以**出现多项（如「月总额度」+「月编程用量」），此时**必须**用 `scope` 区分。
- 绝对用量（`used` / `limit`）与相对时间（`resetInSec`）**不在本契约内**：实测提供方都只给百分比与重置时刻；将来需要时**必须**按受控字段扩展，**不得**擅自添加。

**`extraQuotas` 规则**

- 每一项**必须**有 `label`、`amount`、`currency`。
- `progress` 存在时，`used` **必须**是数字，`limit` **必须**是正数或 `null`（`null` 表示无上限）。
- `label` 是数据描述（如「加油包」「额外额度（结转）」），**可以**是中文；这不是"展示文案"。

### 2.3 `billingType = "balance"`

```jsonc
"balance": {
  "amount": 49.59,                  // 必须：实际账面余额，可为负（欠费如实显示）
  "currency": "CNY",                // 必须
  "accounts": [                     // 可以：各币种 / 各分项
    {
      "label": "人民币账户",         // 必须
      "amount": 49.59,              // 必须：该账户总余额
      "currency": "CNY",            // 必须
      "recharged": 40.00,           // 可以：充值部分
      "granted": 9.59,              // 可以：赠送部分
      "spent": 123.45,              // 可以：累计消费
      "parts": [                    // 可以：自定义分项（与 recharged/granted 二选一）
        { "label": "现金", "amount": 40.00 },
        { "label": "代金券", "amount": 9.59 }
      ]
    }
  ],
  "alertThreshold": 2,              // 可以：用户自设的余额预警线（缺省 5）
  "spending": {                     // 可以：消耗统计
    "thisMonth": 1.23,
    "total": 45.6,
    "currency": "USD"
  }
}
```

**`balance` 规则**

- `amount` **必须**是**实际余额**：官方若把欠费 clamp 成 0（如 Moonshot 的 `available_balance`），**必须**用分项之和还原，负数照显。
- `accounts` 有分项时按账户分行渲染；无分项时才单独显示 `amount`，**不得**造成总额与账户行重复。
- `parts` 用于语义自定义的分项（现金/代金券）；没有则回退到 `recharged`/`granted`（充值与赠送）。

### 2.4 完整示例

**订阅额度（Kimi 新套餐）**

```jsonc
{
  "providerId": "kimi-coding",
  "billingType": "quota",
  "status": 1,
  "quota": {
    "plan": "Plus",
    "timeWindows": [
      { "period": "5h",    "usedPct": 8,  "resetAt": 1793793694000 },
      { "period": "month", "usedPct": 33, "resetAt": 1796428800000 },
      { "period": "month", "usedPct": 60, "scope": "code", "resetAt": 1796428800000 }
    ],
    "extraQuotas": [
      { "label": "加油包", "amount": 0, "currency": "CNY",
        "progress": { "used": 12, "limit": 300, "currency": "CNY" } }
    ]
  }
}
```

**按量余额（Moonshot，含欠费）**

```jsonc
{
  "providerId": "moonshotai-cn",
  "billingType": "balance",
  "status": 1,
  "balance": {
    "amount": -26.45,
    "currency": "CNY",
    "accounts": [{
      "label": "人民币账户", "amount": -26.45, "currency": "CNY",
      "parts": [{ "label": "现金", "amount": -26.45 }, { "label": "代金券", "amount": 0 }]
    }]
  }
}
```

**失败（凭证被拒）**

```jsonc
{ "providerId": "commandcode", "billingType": "quota", "status": 4, "message": "API 密钥无效" }
```

## 3. 状态码

### 3.1 编码表

| 码 | 名称 | 含义 | 数据 | 前端表现 |
|---|---|---|---|---|
| **1** | 成功 | 拿到了有效额度/余额 | `quota` 或 `balance` **必须**有内容 | 正常渲染（颜色由判色决定） |
| **2** | 未配置凭证 | 没有 API Key / 认证文件 / 配置无效 | 无 | 灰，「未配置 API Key」 |
| **3** | 未适配 | 插件还不支持这家 | 无 | 灰，「插件未适配，敬请期待」 |
| **4** | 凭证被拒 | 401/403、key 无效或过期 | 无 | 红，`message` |
| **5** | 请求失败 | 网络错误、超时、5xx、响应解析失败 | 无 | 红，`message` |
| **6** | 无有效额度数据 | 请求成功但字段没识别到 / 窗口全缺失 | 无 | 红，`message` 或「未识别到额度字段」 |
| **7** | 无生效套餐 | 账号查得通，但没有生效订阅 | 无 | 灰，「无订阅」 |

### 3.2 判定规则

| 条件 | 码 |
|---|---|
| 抓到有效窗口或余额 | 1 |
| 没有凭证、认证文件读不到、认证字段无效、端点配置被篡改 | 2 |
| 该提供方在插件里没有抓取器 | 3 |
| HTTP 401/403，或平台用业务码表示 key 无效/过期 | 4 |
| 网络异常、超时、HTTP 4xx/5xx、响应无法解析 | 5 |
| 请求成功但没有任何有效窗口/余额字段（含"官方暂未提供查询接口"） | 6 |
| 请求成功、账号有等级但无生效套餐 | 7 |

### 3.3 通用规则

- 只有 `status === 1` 时才有数据；其余状态 `quota` / `balance` **必须**为空。
- `message` 承载细节，状态码只做粗分类。
- `message` **必须**是**固定的可展示短句**（由抓取器给出，不要求全项目统一），且**不得**包含：
  服务端返回的原始错误文本、堆栈、请求头/凭证、URL 或任何账号标识。
  原因是这类信息可能被第三方注入，直接展示会泄露隐私。

**常见的 message 形态**（不穷举，各抓取器可按同一风格自拟）：

```
API 密钥无效
凭证被拒绝（HTTP 401）
凭证已过期，请重新登录
请求超时（10000ms）
HTTP 502
未识别到额度字段
官方暂未提供查询接口
```

## 4. 静态元数据

以下信息与单次抓取无关，由 `/token-monitor/provider-mappings` 下发，**不在快照里**：

| 字段 | 说明 |
|---|---|
| `provider_name` | 展示名 |
| `vendor` / `vendorLabels` | 厂商 id 与显示名 |
| `url` | 官网入口（充值/续费页） |
| `verified` | 是否用真实凭证实测过 |
| `sortOrder` | 展示排序 |

前端渲染时合并两份：`mappings[providerId]`（静态）+ `overview[providerId]`（动态快照）。

## 6. 抓取器实现契约

每个 `fetchXxx(ctx, config)` **必须**自行完成「取数 + 解析 + 封装」，直接返回本契约的快照：

```js
export async function fetchXxx(ctx, config) {
  const key = await resolveCredential(ctx, 'XXX_API_KEY');
  if (!key) {
    return { providerId: 'xxx', billingType: 'quota', status: STATUS.NO_CREDENTIAL };
  }
  const res = await fetchJson(url, headers);
  if (res.status === 401) {
    return { providerId: 'xxx', billingType: 'quota',
             status: STATUS.UNAUTHORIZED, message: 'API 密钥无效' };
  }
  return {
    providerId: 'xxx', billingType: 'quota', status: STATUS.OK,
    quota: { plan, timeWindows: [...], extraQuotas: [...] },
  };
}
```

**规则**

1. 各家原始响应的差异**必须**由抓取器自行消化；中心**不得**假设字段路径、**不得**写提供方专属逻辑。
2. 状态码**必须**用 `STATUS` 常量给出，**不得**写裸数字。
3. `message` **必须**符合 3.3 节的约束（固定短句、不含原始错误与凭证）。
4. 抓取器**不得**返回原始响应（`raw`）、端点地址（`endpoint`）或任何凭证；排障**必须**走服务端诊断日志。
5. 中心只做两件事：`validate()` 校验 + 聚合排序。

## 7. 校验与合规

### 7.1 校验规则

`validate(snapshot)` 是契约的守门人：

| 检查项 | 规则 |
|---|---|
| 必填 | `providerId` / `billingType` / `status` |
| 枚举 | `billingType ∈ {quota, balance}`；`period ∈ {5h, 7d, 30d, month}`；`scope ∈ {total, code}` |
| 范围 | `usedPct` 在 0–100；`status` 在 1–7；`progress.limit` 为正数或 `null` |
| 一致性 | `status === 1` 时有数据且 `quota`/`balance` 与 `billingType` 一致；`status ≠ 1` 时必须为空 |

由于抓取器是自由封装，这道校验是「各家写法可以不同、但产出必须一致」的**唯一保障**。

### 7.2 如何验证一个实现

```js
import { validate, STATUS } from '../lib/util/quota-snapshot.js';
import { FETCHERS } from '../lib/util/fetch-quotas.js';

const snapshot = await FETCHERS.example(ctx, {});
const result = validate(snapshot);
assert.equal(result.ok, true, result.errors.join('; '));
```

`result.errors` 会给出精确路径（如 `quota.timeWindows[0].period 必须是 …`）。

**每个抓取器必须至少覆盖**：

1. 正常快照通过 `validate()`；
2. 状态码：无凭证 → 2、401 → 4、网络失败 → 5、字段缺失 → 6（按该家实际路径）；
3. 数值换算正确（`usedPct` 与原始响应一致）；
4. 返回对象不含 token / 账号 ID / 原始响应。

## 8. 前端展示规则（仅供参考）

> **本章只作说明用途，不是可改动的契约。**
>
> 前端渲染逻辑（`lib/client.js`）由插件维护者统一维护，**不接受**为单家提供方做定制修改。
> 新增提供方时**不需要**阅读本章，也**不得**据此改动前端；
> 这里列出展示规则，是为了让抓取器作者理解「数据会被怎样消费」，从而产出更贴合展示的结构。

### 8.1 文案映射

```js
const PERIOD_LABEL = {
  '5h':  ['5小时用量',  '5h'],
  '7d':  ['7天用量',    '7d'],
  '30d': ['30天用量',   '30d'],
  month: ['本周期用量', '30d'],     // 计费周期（按订购日滚动，非日历月）
};
const SCOPE_CODE_LABEL = '编程用量';  // scope=code 用独立名称，避免与总额度重名
const LONG_PERIODS = ['7d', '30d', 'month'];
```

### 8.2 状态分流

```js
status === 1              → 正常渲染（下面的判色规则）
status === 2 | 3 | 7      → 灰（中性，不抢注意力）
status === 4 | 5 | 6      → 红（告警，显示 message）
```

### 8.3 判色（只有红一档）

```js
// 订阅额度：任一时间窗（5h / 7d / 30d / month，含编程用量）已用 ≥ 90% → 红
// 与弹层进度条共用同一条红线（RED_PCT），两处颜色永远一致
任一 timeWindow.usedPct >= RED_PCT(90)  → 红
// 「已过重置时刻」的窗口按 0% 已用算，避免刚到点还没刷新时误报

// 按量余额
balance.amount <= (balance.alertThreshold ?? 5)    → 红
```

### 8.4 徽标选窗（单值，最长耗尽窗口优先）

```
候选 = 非 scope=code 的窗口，按周期 5h → 7d → 30d/month 排列
从长到短找第一个「已耗尽」（剩余 ≤ 0）的窗口 → 显示它
都不耗尽 → 显示最短窗口
```

例：5h 有余但 7d 耗尽 → 显示 `7d 余 0%`（周额度卡死时显示 `5h 余 100%` 会严重误导）。

### 8.5 文案（剩余口径）

```js
`${PERIOD_LABEL[period][1]} 余 ${100 - usedPct}%` + （可选）`· ${倒计时}`
// 徽标：`5h 余 88%`、`7d 余 0% · 2h 44min`
```

### 8.6 弹层明细

```js
// 窗口行：标签（scope=code → 「编程用量」）+ 倒计时并入标签 + 已用% + 进度条
`5小时用量（2h 44min后重置）`   12%   [进度条]

// 进度条：无黄色档，pct >= 90 红、否则绿；文字按状态染色

// 附加额度（无 progress）：标签 + 金额
`额外额度（结转）`   15.00 CNY

// 附加额度（有 progress，有上限）：一行式，余额与消费并入标签，值=百分比
`加油包（余额 ¥0.00，周期消费 ¥12.00 / ¥300.00）`   4%   [进度条]

// 附加额度（有 progress，无上限）：左右分栏，值显示「无限制」，不画进度条、文字不染色
`加油包（余额 ¥0.00）`   周期消费 ¥5.00 / 无限制
```

### 8.7 全部提供方列表（多值）

```js
// 每行列出各窗口的剩余百分比：
//  7d 见底 → 只显示 7d（不显示 5h）
//  30d / month 始终追加
//  scope=code 的窗口不显示（只在弹层明细看）
`5h 50% · 7d 70% · 30d 80%`
```

## 9. 兼容性与演进

| 变更类型 | 规则 |
|---|---|
| **新增可选字段** | 允许。前端会忽略不认识的字段，因此抓取器可以自由增加 |
| **新增枚举值** | 允许（如新的 `period`）。前端对未知枚举回退到原始值显示 |
| **改字段语义** | 不允许。语义变化**必须**走新字段名，并保留旧字段一个版本周期 |
| **删除字段** | 仅当确认无提供方产出、前端不读取时允许（本契约 1.0 已删除 `used` / `limit` / `resetInSec`） |
| **新增状态码** | 不允许。状态码是受控集合 1–7，不够用时**必须**重新设计分类 |
| **必填改可选 / 可选改必填** | 必填改可选允许；可选改必填**不允许**（会破坏存量实现） |

**前端兼容性**：由插件维护者随契约升级同步维护；第三方**不得**修改前端代码。
抓取器作者只需保证产出符合本契约，前端的展示行为不在其职责范围内。
