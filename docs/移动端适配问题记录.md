## 2. P1：徽标撑破头部工具条（已定位）

### 现象

- 窄屏下同一行的「在编辑器中打开」「下载会话日志」被挤出屏幕右侧
- 徽标与标题区域重叠，文字互相压住看不清
- 截图尺寸 660×266

### 根因

三件事叠加，缺一不可：

1. **注册位置**：徽标注册在 `conversation.session.header.utilities`，`order: -99` 固定排在最左（`lib/client.js` 的 slot 注册，约 L5230–L5249）。同行的官方占用者只有 `open-in-app`（-10）和 `session-log-download`（0），所以被顶掉的正好是徽标后面的这两个。
2. **官方该行不收缩**：`@deepseek-ai/dsh-client-ui-conversation/lib/client.js` 中

   ```
   .wSkVaW_headerUtilities{flex:none; align-items:center; gap:8px; margin-left:20px; display:flex}
   .wSkVaW_titleCluster{flex:1; min-width:0; display:flex}
   ```

   `flex:none` 意味着这一行**永远不会缩**，内容多宽就占多宽，超出部分直接溢出到视口外。
3. **我们的胶囊没有宽度上限**：徽标 = 状态圆点 + 文字「模型名 · 余量」（如 `deepseek-v4-flash · 7d 剩 87%`），样式是 `white-space: nowrap` 且**没有 max-width**（`lib/client.js` 的 `S.trigger` / `S.badge`，约 L633–L646；渲染在 L1586–L1598，文案拼装在 L1544–L1557）。

第 3 点是本插件唯一该负责的部分：官方同类控件都有上限（模型选择器 `max-width:220px`、代理预设 `180px`、子代理切换 `244px`），我们一个都没有。

### 修复方案（待实施）

1. **给文字加 `max-width` + 省略号**——纯 CSS 一行改动，保证任何屏宽都撑不破工具条；完整文案已有 `title` 悬浮提示，截断不丢信息。
2. **窄屏只留状态圆点（提示灯）**——采纳 issue 的建议：绿/黄/红 = 余量充足/告急/耗尽，隐藏模型名与百分比；圆点仍可点击展开完整面板。实现上复用仓库已有的幂等注入模式（`style[data-plugin-css="…"]`，见 `lib/client.js` 约 L4137–L4156），在媒体查询里把文字 span 关掉，保留 `title` / `aria-label`。
3. **断点对齐官方**：官方模型选择器在容器 ≤460px 时隐藏文字只留图标（`@container (width<=460px){…triggerLabel{display:none}}`）。官方用的是 container query，而头部这一层拿不到容器上下文，因此本插件用 viewport 媒体查询（移动端头部占满宽度，两者等价）。

### 明确不动的部分

- 不改 `order: -99`（左钉位置是刻意的，见注册处注释）
- 不改弹层宽度（已经是 `min(380px, 100vw - 32px)`，移动端本身就安全）

## 3. P2：模型选择 / 推理深度被推出屏幕（待确认）

### 现象

- 只装 DSH 时该区间在屏幕内；装本插件后有一部分跑到屏幕外
- 截图尺寸 600×1200（竖屏两张）

### 当前判断

**主因假设**：P1 的连带结果。头部那一行不收缩、被徽标撑宽后整列出现横向溢出，composer 右侧控件被一起推出视口。

**依据**：本插件只注册了三个位置——`conversation.session.header.utilities`、`conversation.view`、`settings.section`；模型选择器所在的 `conversation.input.model`（composer 工具行）**没有本插件的任何注册**，推理深度同理。注入的全局样式也只有两个带作用域前缀的（`.tm-settings-btn-*`、`.tm-settings-scroll`），不存在全局 CSS 泄漏。

**备选假设**：`conversation.view` 里新增的「用量」页签让头部导航变宽，同样挤压窄屏布局。

### 判定方法（关键）

用 A/B 对照直接定归属，不要靠猜：

1. 在窄屏宽度下，记录 composer 那一行的位置 + 执行 `document.documentElement.scrollWidth + " / " + window.innerWidth`
2. 到 设置 → 插件 里临时**停用** Token Monitor，同一宽度再看一次
3. 回到屏幕内 → P2 是本插件引起（随 P1 一起修）；仍在屏幕外 → 是官方布局问题，插件侧无从干预，应上报 DSH

## 4. 验证方法

### 可行：桌面浏览器设备模拟

`F12` → `Ctrl+Shift+M`，选 `iPhone 14 Pro`（393×852）或手动拖到 375×667。

- 布局宽度问题可如实复现；设备模式**不能**还原的只有真机触摸行为、iOS 安全区（`safe-area`）与字体渲染差异——对本问题无影响
- 诊断式：`document.documentElement.scrollWidth > window.innerWidth` 即确认存在横向溢出

### 不可行：真机局域网直连（环境限制）

| 事实 | 出处 |
|---|---|
| webserver 的 `host` 只接受 `127.0.0.1` 或 `0.0.0.0` 两个字面量，无法绑定具体局域网 IP | `@deepseek-ai/dsh-host-webserver/lib/index.js`<br>`z.union([z.const("127.0.0.1"), z.const("0.0.0.0")])` |
| CLI 明确拒绝 `--host 0.0.0.0`，理由是会"把远程代码执行暴露到网络" | `@deepseek-ai/dsh-web-app/lib/startup.js` |
| `lanAddresses` 只在绑定 `0.0.0.0` 时才有值，启动日志里的 `(LAN: …)` 行也只在那种情况下出现 | `@deepseek-ai/dsh-web-app/lib/index.js` `resolveLanTrust()` |

所以默认配置下手机连不上 `dsh web`；启动日志里看不到 `(LAN: …)` 就是这种情况。

需要澄清的一点：**本插件的来源校验不是障碍**。一旦绑定 `0.0.0.0`，`trustedHosts` 会自动带上局域网地址，本插件的 `denyUntrusted` / `isTrustedRequest` 会正常放行（`lib/util/http-guard.js`）。

第三方方案 `@linxin666/dsh-remote-web-ui`（cloudflared 隧道 + 配对，需要局域网/隧道）已于 2026-09-14 安装尝试后卸载，不作为本问题的验证路径。

**结论**：移动端验证目前只能靠桌面 devtools 设备模拟。
